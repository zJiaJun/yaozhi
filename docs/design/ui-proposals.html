遥指 Yaozhi · 界面方案

三个设计方向 + 共用的首次设置向导。面板里的"按住说话"按钮、遥控器上的按键都可以点，用来演示状态变化。界面按 MyGo 原生组件能实现的范围设计（菜单栏弹出面板、侧边栏、开关、分段控件、电平条、矢量绘图）。

方案 A · 原生克制

像 macOS 的"控制中心"和"系统设置"：菜单栏面板是几行状态和开关，设置窗口是左侧栏 + 分组列表。遥控器图只在"按键"页出现。

好处

  • 一眼像系统自带工具，学习成本最低
  • MyGo 原生组件直接拼，工作量最小
  • 设置项多了也不乱

代价

  • 辨识度弱，"用遥控器控制 Mac"的感觉不强
  • 链路出问题时，要逐行看哪一项变黄

方案 B · 遥控器为中心

主窗口就是一支矢量遥控器：点哪个键就在右边配置哪个键，语音键点开就是语音设置。按下实体键时图上实时高亮。菜单栏面板也放一支小遥控器。

好处

  • 和"用遥控器控制 Mac"的定位最贴，辨识度高
  • M2 的按键映射、单击/双击/长按天然有位置
  • 换设备时只换一张矢量图和键位表，正好对应设备适配层

代价

  • 要画、要维护每款设备的矢量图
  • M1 只有语音时，整张遥控器大多数键还是"未开放"
  • 链路状态需要另找位置放

方案 C · 链路仪表盘

把"遥控器 → 遥指 → BlackHole → Typeless"这条链路画出来，每一环都有状态灯，说话时能看到声音一路流过去。按键映射作为单独一页。

好处

  • 哪一环坏了一眼就知道，最利于排查和首次设置
  • 把"等播完再结束"等时序做成可见的数据，方便调优
  • M3 接入更多设备时，左边的节点换成设备列表即可

代价

  • 偏工程味，日常用户其实只关心"能不能用"
  • 按键映射不在主视图，弱化了长期核心

首次设置向导

第一次打开时出现，三个方案共用。每一步都自动检测，做完自动打勾；可以随时从设置里重新打开。

用户要亲手做的

  • 配对遥控器（一次）
  • 点"允许"授权蓝牙、辅助功能
  • 装原版 BlackHole（向导给命令）
  • 在 Typeless 里选 yaozhi-mic（一次）

欢迎使用遥指
A · 原生克制B · 遥控器为中心C · 链路仪表盘
打开后先看到设备状态和开关列表一支遥控器四个节点的链路图
贴合产品定位一般最强（控制 Mac 是长期核心）偏语音
M1（只有语音）合适大部分键暂未开放，略空最合适
M2（按键映射）能用，但要另画遥控器最合适要单独一页
排查问题逐行看状态需另放链路状态最直观
多设备（M3）列表加一行每款设备一张矢量图链路左端换成设备列表
MyGo 实现量小中（矢量遥控器、命中区域、高亮动画）中（链路动画、事件流）

我的推荐：B 做骨架，A 做设置页，C 的链路条放进面板和诊断

  • 主窗口用 B：遥控器是主角，点语音键进语音设置，点其他键进按键设置（M1 时其他键显示"M2 开放"）。这样从第一版起界面就在讲"用遥控器控制 Mac"。
  • 设置细项（设备、权限、诊断、关于）用 A 的系统设置风格分组列表，放在左侧栏里，跟遥控器页并列。
  • 菜单栏面板用 C 的四节点链路条 + A 的开关：日常一眼确认"能不能用"，说话时能看到声音流过。
  • 向导最后一步"试一试"复用链路条，和日常面板长得一样，用户学一次就懂。
